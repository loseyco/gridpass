## 2. Logic Chain
1. **Pre-Arrival Lockout Resolved**:
   - By specifying a dual-pass lifecycle (Observation 1.1), passes are bifurcated into pre-arrival and on-demand passes.
   - Pre-arrival passes are valid for the *entire active duration of the event* (e.g., 24 hours). Therefore, pre-registered passes downloaded 24 hours prior will not be flagged as expired by the offline scanner.
   - The security of longer validity pre-arrival passes is maintained by strictly checking against the localized double-scan replay cache to prevent duplicate reuse, and checking the decrypted passenger names/tow vehicle plates displayed on-screen (Screenshot Evasion Guards).
   - This resolves the operational lockout gap.

2. **Waiver Collision Prevented**:
   - Changing the Protobuf metadata fields from truncated 32-bit hex strings to raw binary `bytes` of 8 bytes (64 bits of entropy) preserves serialization overhead (exactly 8 bytes) while elevating security (Observation 1.2).
   - Under the Birthday Paradox, the collision threshold moves from $2^{16} = 65,536$ trials (32-bit) to $2^{32} \approx 4.29$ billion trials (64-bit).
   - Standard mobile devices can brute-force $2^{16}$ variations in under 1 second. Elevating this to 64-bit entropy means finding a collision requires $2^{32}$ variations, which would take over 11 hours of intensive mobile computation, making brute-force waiver evasion impossible.
   - This resolves the legal waiver bypass gap.

3. **Trial Verification DoS Neutralized**:
   - Including `uint32 signing_key_id = 3;` in the outer `SignedSecurePass` envelope (Observation 1.3) allows the offline scanner to immediately perform an O(1) key store lookup to select the exact public key needed.
   - If the key is not in the store or is invalid, the pass is rejected instantly, without performing heavy cryptographic verification.
   - This prevents trial verification loops where the terminal is forced to perform signature checks using all $N$ active keys. In an environment with 50 active keys, this reduces the signature verifications required for an attack pass from 50 to 0 (if key ID is invalid) or 1 (if key ID is valid), protecting the terminal from DoS.
   - This resolves the CPU-exhaustion DoS gap.

4. **Cryptographic Terminology Corrected**:
   - The terminology has been corrected from mathematically incorrect "decrypt and verify" to "decode the outer envelope and verify the Ed25519 signature over the raw serialized metadata bytes using the pre-loaded public key" (Observation 1.4).
   - Since Ed25519 is an EdDSA signature scheme, signatures are verified over the raw bytes, not decrypted.
   - This resolves the terminology contradiction gap.

5. **Additional Platform and Operational Vulnerabilities Remediation**:
   - Abandoning background NFC/BLE active handshakes for client devices avoids platform sandbox locks on iOS, while relying on foreground Wi-Fi sync and native Apple/Google Wallet lockscreen geofences preserves offline capabilities.
   - The mesh sync loss threshold was raised from 30 seconds to 3 minutes, which suppresses alarm fatigue on short diesel rig signal drops. Silent orange banners warn operators of sync loss, while loud alarms remain reserved only for critical double-scans. Plate-matching is enforced to permit override in Isolated Mode.
   - Solar Light Mode enforces DOM-inlined SVGs to prevent invisible partner logos and keeps green borders visible to preserve the marshal's 10-foot visual check cue under 10,000+ nits glare.
   - PWA Private Mode detection instructs users to switch to standard browsing, preserving IndexedDB waiver custody.
   - Standard, publicly trusted Let's Encrypt wildcard certs are served on the local gateway via a wildcard sub-domain mapping to private IP (`*.local.gridpass.app` -> `192.168.1.50`), keeping the wildcard private key safely stored on cloud servers.
   - These remediations comprehensively solve Gaps 4, 5, and 6.
